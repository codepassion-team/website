# Domain Docs

This is a single-context repo. The root `CONTEXT.md` holds shared domain vocabulary; `docs/adr/` holds architecture decisions.

## Before exploring

Read `CONTEXT.md` and ADRs in `docs/adr/` that relate to the work. If either does not exist, proceed without flagging its absence or creating it upfront. Domain-modeling work can add these files when terms or decisions are resolved.

## Use the project's vocabulary

Use terms defined in `CONTEXT.md` in issue titles, proposals, tests, and implementation notes. If a needed concept is missing, reconsider the term or note a gap for domain modeling.

## Flag ADR conflicts

If proposed work contradicts an existing ADR, identify the decision and explain why it should be revisited rather than silently overriding it.
